## Состояние проекта

> Это ветка `android` репозитория [detestern/KarinCore](https://github.com/detestern/KarinCore). Десктопный клиент для Linux находится в `main`; Android-сборки публикуются как пре-релизы с тегами `android-v<версия>`.

Это экспериментальный Android-порт [detestern/KarinCore](https://github.com/detestern/KarinCore). За основу взят KarinCore 1.3.7, commit `b7fea2e2ff5e1492fd863381985fdebb4da7a57e`.

В Android-порте сохранены интерфейс на TypeScript/Vite и общая Rust-логика KarinCore: парсинг ссылок, подписки, маршрутизация, DNS и профили. Linux-часть с `sudo`, systemd, `route.sh`, iptables и системным Xray на Android заменена нативным `VpnService`.

Версия `0.1.0-alpha.32` распространяется через GitHub prereleases отдельными debug APK для `arm64-v8a`, `armeabi-v7a`, `x86` и `x86_64`. Следующий контрольный этап: запуск и проверка на реальных Android-устройствах.

## Реализовано к 0.1.0-alpha.32

- мобильная точка входа Tauri 2;
- Android `VpnService`;
- foreground service;
- настоящий TUN с IPv4 и IPv6;
- Xray через закреплённый `AndroidLibXrayLite v26.9.30`;
- базы `geoip.dat` и `geosite.dat` поставляются внутри APK, атомарно извлекаются в приватный каталог приложения до запуска Xray и позволяют применять правила `geoip:*` / `geosite:*` без отдельной загрузки;
- передача TUN FD напрямую в `CoreController.startLoop(...)`;
- существующие парсеры KarinCore для VLESS/Reality, VMess, Trojan и Shadowsocks;
- маршрутизация Direct / Proxy / Block;
- DNS-пакеты из TUN направляются в Xray `dns-out`;
- собственный пакет KarinCore исключён из VPN, чтобы Xray не завернулся сам в себя;
- команды prepare/start/stop/status;
- закрытие Activity/WebView не отключает foreground VPN;
- Android P+ отслеживает смену underlying network; при переходе Wi-Fi/сотовая сеть Xray перезапускается без пересоздания TUN;
- выбор приложений для VPN с режимами «Все приложения», «Только выбранные» и «Выбранные мимо VPN»;
- список запускаемых Android-приложений получается нативно, поддерживает поиск и сохраняет выбранные пакеты;
- нативный буфер событий VPN/Xray подключён к существующей вкладке Logs: запуск, ошибки, режим маршрутизации приложений, смена сети и status-события Xray;
- экспорт профилей через системный Android document picker;
- отдельная мобильная раскладка без desktop titlebar, с safe-area отступами и вертикальной маршрутизацией на узких экранах;
- мобильный интерфейс удерживает кнопку конфигураций над системной навигацией, адаптирует формы, карточки профилей, логи и страницу «О проекте» к узким и низким экранам и показывает состояние ядра `idle` вместо технического `null`;
- маршрутизация и настройки на Android разделены на карточки и используют единую прокрутку страницы; история обновлений выводится отдельными блоками версий и пунктами изменений;
- мобильная раскладка и номер встроенной версии больше не зависят от успешного ответа native-команды метаданных: desktop titlebar не перекрывает статус-бар Android, настройки сохраняют прокрутку, а страница «О проекте» использует одну последовательную панель на Android и desktop;
- системная кнопка Android «Назад» сначала закрывает активное окно или панель, из любого раздела возвращает на главный экран, а на главном экране требует повторного нажатия для выхода;
- страница «О проекте» встраивает собственный `CHANGELOG.md` репозитория, поэтому история соответствует релизам KarinCore Android, а не унаследованным заметкам upstream;
- компактный Android-виджет 1×1 одним нажатием подключает или отключает последний успешно использованный VPN-профиль; серая кнопка означает отключение, розовая — подключение, зелёная — активный VPN;
- данные повторного подключения виджета зашифрованы через Android Keystore; перед первым использованием нужно выдать разрешение VPN и один раз успешно подключиться в приложении, а системная «Постоянная VPN» по-прежнему управляется через настройки Android;
- каждый prerelease содержит отдельные APK для `arm64-v8a`, `armeabi-v7a`, `x86` и `x86_64`; CI проверяет наличие соответствующих нативных библиотек KarinCore и Xray в каждом файле;
- версия и update checker получают номер релиза из Rust-пакета вместо хардкода во frontend;
- package visibility для launcher-приложений объявлена явно, чтобы список per-app routing не обрезался на Android 11+;
- восстановление сети обрабатывает как make-before-break, так и break-before-make сценарии;
- после пересоздания Activity/WebView интерфейс восстанавливает состояние подключения из нативного VPN-сервиса; устаревшее frontend-состояние удаляется, если сервис уже не работает;
- поддерживается системный режим Android «Постоянная VPN»: последний успешно запущенный нативный конфиг сохраняется для системного рестарта и восстановления после перезагрузки;
- из настроек KarinCore открывается системный экран VPN для включения «Постоянной VPN» и «Блокировать подключения без VPN»;
- интерфейс показывает состояние Always-on/lockdown и не изображает обычное отключение доступным, когда системный Always-on активен;
- в настройках добавлена живая диагностика разрешений и стабильности Android: разрешение VPN, уведомления foreground-сервиса, оптимизация батареи, фоновые ограничения, экономия трафика, доступность и валидация сети, а также Always-on/lockdown; для каждого исправляемого предупреждения открывается соответствующий системный экран, а OEM-ограничения фоновой работы отмечаются отдельно, поскольку стандартный Android API не раскрывает их состояние;
- на Android подписки загружаются нативно через Kotlin HTTP вместо Rust reqwest, с таймаутами подключения/чтения, ограничением редиректов и отдельными ошибками TLS/сети;
- поддерживаются встроенные маршруты подписок V2RayTun: Base64-профиль из HTTP- или body-заголовка `routing` принимается как объект `{"rules":[...]}` или корневой массив `[...]`, проверяется, сохраняется вместе с группой и автоматически применяется к её серверам с исходным порядком правил, полями `port`, `domainStrategy` и `domainMatcher`; раздел маршрутизации показывает фактически выбранный маршрут, источник, сервер, состояние применения и полный упорядоченный список правил, а Direct / Proxy / Block переключаются на данные подписки в режиме только для чтения;
- Ссылки маршрутизации Happ (`happ://routing/add/…`) и маршруты из полных JSON-подписок сохраняются отдельным профилем с именем провайдера. Профиль не применяется автоматически и не затрагивает твои правила и DNS; его выбирают кнопкой «Выбрать» на странице маршрутизации.
- установка системных зависимостей в Rust CI не перезапускает службы GitHub runner, поэтому проверка не обрывается после `apt`;
- во frontend добавлен независимый watchdog на 25 секунд, поэтому интерфейс больше не может бесконечно оставаться в Loading даже при зависшем native bridge;
- для Android `reqwest` использует Rustls;
- во вкладке Logs добавлена самопроверка VPN: состояние нативного сервиса, Xray, TUN, принудительный proxy-path с DNS/HTTPS и внешний IP через активный прокси.

Пока не реализованы: OpenVPN chaining и дополнительная проверка runtime на реальном устройстве. Always-on/lockdown, IPv6 и OEM-особенности требуют проверки на реальном устройстве.

## Виджет рабочего стола

Виджет 1×1 `Переключатель KarinCore VPN` использует последний профиль, с которым приложение успешно подключилось. Перед добавлением виджета выполняется одно обычное подключение в KarinCore, после чего виджет добавляется через меню виджетов Android-лаунчера.

Одно нажатие подключает или отключает VPN. Серый цвет означает отключение, розовый — подключение, зелёный — активный VPN. Если разрешение VPN ещё не выдано или успешный профиль не сохранён, виджет открывает KarinCore для завершения настройки. При включённой системной «Постоянной VPN» нажатие для отключения открывает настройки VPN Android, поскольку приложение не может самостоятельно отключить этот режим.

## Диагностика разрешений и стабильности

В настройках Android проверяются системные условия, влияющие на длительную работу VPN. Зелёные пункты готовы, предупреждения требуют внимания, информационные пункты являются необязательными или не могут быть проверены через стандартный Android API.

Диагностика не меняет системную политику скрытно. Согласие на VPN запрашивается стандартным диалогом Android, а настройки уведомлений, батареи, фонового трафика, приложения и Always-on открываются на соответствующих системных экранах. Для батареи используется обычный список оптимизации без чувствительного разрешения на прямое исключение.

## Архитектура APK

- `arm64-v8a` — почти все современные Android-смартфоны и планшеты;
- `armeabi-v7a` — старые 32-битные ARM-устройства;
- `x86_64` — 64-битные Android-эмуляторы Intel/AMD и совместимые устройства;
- `x86` — старые 32-битные x86-эмуляторы и устройства.

APK с неподходящей архитектурой отклоняется Android и не заменяет установленное приложение.

## Первый запуск сборки

Нужны Rust, Node.js, Android Studio, Android SDK, Platform Tools, Build Tools, NDK и Command-line Tools.

Для сборки добавляются Android targets:

```bash
rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
```

Последовательность первого запуска:

```bash
git clone -b android https://github.com/detestern/KarinCore.git
cd KarinCore

npm install
npm run android:core
npm run android:init
npm run android:dev
```

`android:core` скачивает закреплённый `libv2ray.aar` и проверяет SHA-256. Сам AAR в Git не хранится.

После первого успешного `tauri android init` воспроизводимые файлы из `src-tauri/gen/android` могут быть добавлены в репозиторий. Машинный `local.properties` исключён через `.gitignore`.

## Версии

Android-порт имеет свою ветку SemVer и не обязан повторять номер Linux-версии.

Проверка перед релизным коммитом:

```bash
npm run version:check
```

Скрипт проверяет совпадение версии в `VERSION`, `package.json`, `src-tauri/Cargo.toml` и `src-tauri/tauri.conf.json`. Android `versionCode` должен только увеличиваться.

Для публикации debug prerelease требуется явное разрешение в настройках репозитория или маркер `[publish-debug]` в коммите `release:`. Обычный коммит с новой версией не публикует APK с тестовой подписью автоматически.
